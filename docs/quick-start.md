# Quick Start

## Create a project

After `create-spellwire` is published:

```bash
bun create spellwire my-automation
cd my-automation
bun run typecheck
bun run build
```

The initializer installs `spellwire` by default. Pass `--no-install` when scaffolding offline.

## Add to an existing project

```bash
bun add spellwire
```

Create `macro.spellwire.ts`:

```ts
import { Key, rt, tapKey } from "spellwire";

let presses = 0;

rt.onKeyDown(Key.Q, () => {
  presses += 1;
  if (presses % 2 === 0) tapKey(Key.E);
});
```

Compile it:

```bash
bunx spellwire compile macro.spellwire.ts
```

The compiler writes:

```text
macro.spellwire.bin
macro.spellwire.bin.json
```

The JSON file contains persistent-state slots and program metadata. The binary is consumed by `spellwire-core` through the `spellwire-native` host ABI.

## Try the repository before the first npm release

```bash
git clone https://github.com/eunhhu/spellwire.git
cd spellwire
bun install
bun run typecheck
bun run test:ts
bun run compile:example
cargo test --workspace
cargo build -p spellwire-native --release
```

## Alpha capability boundary

Currently implemented:

- stateful TypeScript compilation
- `if`, loops, arithmetic, helper functions, and early return
- keyboard/mouse output bytecode
- held-input queries and microsecond deadlines
- Rust VM and stable host C ABI
- JavaScript fallback intrinsics for unit tests
- npm-ready `spellwire` and `create-spellwire` packages

Not yet bundled in the npm package:

- validated global Windows/macOS/Linux observers
- validated native key/mouse injectors
- prebuilt native libraries
- transparent native overlay renderers

Until those backends land, use the generated bytecode with the native host ABI or test the compiler/fallback lane.
